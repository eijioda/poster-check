## 0. この文書のゴール

いまのアプリは「ポスターを上げる → AIが指摘を並べる」で終わっている。
実際の現場は **アミーゴ（中高生）が作る → ディレクターが見る → 直してと伝える → 直る** という往復なので、
アプリもその往復に沿った形にしたい。

この設計書で決めること:

1. 誰がどの画面を使うか（中高生用／ディレクター用の作り分け）
2. 画面の並べ方（下タブ3つ: ポスターチェック／アンケート／ディレクター管理）
3. **チェック結果から「ディレクターがアミーゴに送るFB文」を作るところまで**
4. スマホで気持ちよく使えるようにするための基準

実装はしない。ただし「どこを触ればできるか」まで書いてあるので、承認が出たらそのまま着手できる。

## 1. いまの困りごと（現状分析）

コードを読んで見つかった、使いにくさの原因。

| # | 困りごと | 原因（該当箇所） |
|---|---------|-----------------|
| 1 | 1画面が縦に長すぎる。スマホだとスクロールが終わらない | `app/page.jsx` が430行で、アップロード・チェック結果・アンケート作成・フォームプレビュー・QR・Apps Scriptを全部1画面に載せている |
| 2 | 中高生もディレクターも同じ画面を見ている | 役割の概念がそもそもない |
| 3 | **チェック結果が「指摘の羅列」で終わる**。人に伝える形になっていない | `app/page.jsx` の findings 表示と `downloadMarkdown()` まで。Markdownは会議資料向きで、LINEに貼るには不向き |
| 4 | 一度作ったアンケートに、あとから辿り着けない | `surveyStore.js` はID指定の取得のみ（`getSurvey(id)`）。一覧を返す関数がない。URLを失くしたら終わり |
| 5 | 同じ企画のチェック結果とアンケートが紐づかない | `checkStore` と `surveyStore` が独立。企画（ワークショップ）という単位が存在しない |
| 6 | 画面の行き来ができない | ナビは `/rules` へのテキストリンク1本だけ |
| 7 | 「誰の企画か」が残らない | アンケート作成時の「作成者名」だけ。チェック結果には作成者すら入らない |

→ **4・5・7は「ディレクター管理画面」を作るうえでの前提が欠けている状態**。
　画面を作る前に、保存の形を足す必要がある（→ 7章）。

## 2. 登場人物と、やりたいこと

### 👦 アミーゴ（中高生・ポスターを作る人）

| やりたいこと | いまの状態 |
|-------------|-----------|
| 作ったポスターが大丈夫か、自分で確かめたい | ○ できる |
| 何をどう直せばいいか、手順で知りたい | △ 指摘は出るが、消し込めない・コピーできない |
| 直したらもう一度見てほしい | △ 共有リンクは出るが、送る導線がない |
| スマホだけで完結したい | △ 縦に長い・タップしづらい |

**使う端末: ほぼスマホ。** ここを最優先にする。

### 🧑‍🏫 ディレクター（見る人・伝える人）

| やりたいこと | いまの状態 |
|-------------|-----------|
| いま動いている企画を一覧で見たい | ✗ できない |
| どの企画が「FB待ち」か知りたい | ✗ 状態の概念がない |
| **指摘をもとに、アミーゴに送る文章を作りたい** | ✗ 手で書いている |
| 言い方をやわらかくしたい／厳しくしたい | ✗ |
| 伝えなくていい指摘を落としたい | ✗ AIの指摘が全部出てしまう |
| 申込・アンケートの回答状況を見たい | △ URLを知っていれば見られる |

**使う端末: スマホ（現場）＋PC（事務作業）。** 両対応。

## 3. 全体構造（下タブ3画面）

画面下に固定タブを置き、3つの入口に分ける。

```
┌───────────────────────────────┐
│                               │
│         各画面の中身          │
│                               │
│                               │
├───────────────────────────────┤
│   🖼        📋        🗂       │   ← 高さ 56px + セーフエリア
│ ポスター  アンケート  管理     │
└───────────────────────────────┘
```

| タブ | パス | 誰が使う | 中身 |
|------|------|---------|------|
| 🖼 ポスターチェック | `/` | 両方 | アップロード → 結果 →（ディレクターは）FB文作成 |
| 📋 アンケート | `/forms` | 両方 | 作成 ＋ **自分が作ったフォームの一覧**（今ここが無い） |
| 🗂 ディレクター管理 | `/admin` | ディレクターのみ | 企画一覧・FB状況・回答数・チェックルール編集 |

**3つ目のタブの見え方:**
- 中高生モード … タブ自体を出さない（2タブ表示）
- ディレクターモード … 3タブ表示

> なお `/rules`（チェックルール編集）は、中高生が触るものではないので **管理タブの中に移す**。
> 今はトップの目立つ位置にリンクがあり、中高生が誤って開けてしまう。

## 4. 画面設計

### 4-1. 🖼 ポスターチェック（中高生モード）

「指摘リスト」ではなく **「直すことリスト」** にする。

```
┌───────────────────────────────┐
│ ポスターチェック              │
│                               │
│  ┌─────────────────────────┐  │
│  │  📷 写真をとる           │  │  ← スマホは撮影を第一候補に
│  │  🖼 アルバムから選ぶ     │  │
│  │  （ここに貼り付けもOK）  │  │  ← Ctrl+V / ⌘V でスクショ貼付
│  └─────────────────────────┘  │
│                               │
│  ┌──────プレビュー──────┐    │  ← 縦長ポスター用に max-height:55vh
│  │                       │    │
│  └───────────────────────┘    │
├───────────────────────────────┤
│ [    チェックする（約30秒）  ] │  ← 画面下に固定（sticky）
└───────────────────────────────┘
```

チェック後:

```
┌───────────────────────────────┐
│  ❌ 2   ⚠️ 3   💡 1           │  ← 件数バッジ。タップで絞り込み
│                               │
│  あと 5 件                    │
│  ▓▓▓▓▓░░░░░░░░░░  1/6         │  ← 進捗バー
│                               │
│  ┌─────────────────────────┐  │
│  │ ☐ 駐車場の場所がない     │  │  ← チェックを付けると消し込み
│  │   会場の住所はあるが…    │  │
│  │   ┌───────────────────┐ │  │
│  │   │✏️ 駐車場: 旧五十沢 │ │  │
│  │   │  中学校グラウンド  │ │  │
│  │   │           [コピー] │ │  │  ← Canva等にそのまま貼れる
│  │   └───────────────────┘ │  │
│  └─────────────────────────┘  │
│  ┌─────────────────────────┐  │
│  │ ☑ 終了時刻がない  （済） │  │  ← 済みは薄く、下へ
│  └─────────────────────────┘  │
│                               │
│  [ 📤 ディレクターに見てもらう ]│  ← 共有リンクをコピー／LINE送信

└───────────────────────────────┘
```

**ポイント**
- 「消し込める」ことで、作業リストとして成立する。チェック状態は端末内に保存（localStorage、キーは `shareId`）
- 修正案は**1タップでコピー**。中高生はCanvaに貼るので、ここが一番効く
- 「ディレクターに見てもらう」は既存の `shareId`（`/c/{id}`）をそのまま使える。LINEで送る導線をつけるだけ
- 用語はやさしく。`severity` のような語は出さない（現状も日本語なのでOK）

│  ☑ ❌ 駐車場の場所がない      │  ← 外すとFB文に入らない
│  ☑ ❌ 終了時刻がない          │
│  ☑ ⚠️ 連絡先が違う            │
│  ☐ 💡 改行位置                │  ← AIが拾いすぎた指摘は落とす

## 5. FB文の設計（詳細）

### 5-1. 作り方

既存のチェック結果（`summary` / `passed` / `findings`）はサーバに保存済み（`checkStore.js`）。
**画像を送り直さず、保存済みJSONだけを材料にテキスト生成する。**

```
[チェック実行] ──> /api/check ──> 画像 + ルール → GPT（高い・30秒）
                                      │
                                      └→ checkStore に保存（shareId）
                                                  │
[FB文つくる] ──> /api/feedback ──> 保存済みJSON + 設定 → GPT（安い・2秒）
                    ↑                                       │
                    └───── 言い方を変えて作り直す ←─────────┘
```

こうすると「言い方を変えて作り直す」が **2秒・0.1円未満** で何度でもできる。
チェックの中で同時に作ってしまうと、作り直すたびに30秒と数円かかるので分ける。

### 5-2. 入力（リクエスト）

```jsonc
POST /api/feedback
{
  "checkId": "xYz123abc",          // 保存済みチェック結果のID
  "to": "さくら",                   // 宛名
  "projectName": "古着リメイク市",  // 企画名（ポスターから自動）
  "deadline": "9/26(金)",           // 直してほしい期限（任意）
  "include": [0, 1, 2, 4],          // 伝える指摘のindex（外した指摘は渡さない）
  "tone": "gentle",                 // gentle | normal | firm
  "length": "normal",               // short | normal | long
  "channel": "line",                // line | mail
  "withLink": true                  // 末尾に /c/{id} を付けるか
}
```

### 5-3. 出力（レスポンス）

```jsonc
{
  "message": "（そのままコピーして送れる本文）",
  "parts": {
    "greeting": "さくらさん、ポスターありがとう！",
    "good": ["日時と会場がはっきり書けていて分かりやすい"],
    "mustFix": [
      { "title": "駐車場の場所", "how": "会場の下に1行足す", "example": "駐車場: 旧五十沢中学校グラウンド" }
    ],
    "niceToHave": [
      { "title": "企画名に注釈", "how": "「古着リメイク市」だけだと、リメイク体験なのか販売なのか分かりにくい" }
    ],
    "closing": "9/26(金)までに直してもらえると助かります！"
  },
  "charCount": 284,
  "costYen": 0.06
}
```

`message` をそのまま編集欄に出す。`parts` は将来「この段落だけ作り直す」に使えるので持っておく。

### 5-4. プロンプトの方針

```
あなたは南魚沼市 mirai塾のディレクターです。
中高生（アミーゴ）が作ったポスターへの指摘を、本人に直接送る
メッセージに書き直してください。

# 大原則
- 相手は中学生・高校生。萎縮させない。ダメ出しの列挙にしない
- 「よかったところ」→「直してほしいところ」→「ひとこと」の順
- 直してほしいところは、必ず **どう直すか（具体案）** まで書く
- 「〜してください」より「〜してもらえると助かります」
- 指摘は渡されたものだけ。ポスターを見ていないことを匂わせない

# 言い方（tone）
- gentle … 初めて／1年生向け。クッションを厚く。必須だけ伝える
- normal … ふだん
- firm  … 公開直前。締め切りを明確に。ただし人格には触れない

# 長さ（length）
- short  … 150字前後。LINEで1画面に収まる
- normal … 300字前後
- long   … 500字前後。理由まで書く

# 送り先（channel）
- line … 改行多め・絵文字ひかえめに可・あいさつ短く
- mail … 件名つき・「お疲れさまです」から始める・署名欄を空ける
```

### 5-5. 文例（tone=gentle / length=normal / channel=line）

```
さくらさん、ポスターありがとう！

日時と会場がはっきり書いてあって、ぱっと見て分かりやすかったです◎
イラストもかわいい！

公開する前に、2つだけ直してほしいところがあります。

①駐車場の場所
　会場の住所の下に1行足してもらえますか。
　例）駐車場: 旧五十沢中学校グラウンド

②終わりの時刻
　「10:00〜」だけだと、何時に終わるか分からなくて
　保護者の方が予定を立てにくいです。
　例）10:00〜12:00

あと余裕があれば、企画名に短い説明があるともっと伝わります。
「古着リメイク市」だけだと、自分で作る体験なのか、
買えるお店なのか迷うかも。

9/26(金)までに直してもらえると助かります。
分からないところがあったら聞いてね！
```

これが **「チェック部分 → ディレクターがアミーゴに送るFB文」のゴール**。

### 5-6. 伝えない指摘を落とせること

AIは 💡改善提案 を拾いすぎる傾向がある（改行位置など）。
全部送ると中高生が「ダメ出しの山」に見えてしまうので、
**送る前にディレクターがチェックを外せる**のは必須。既定値:

- ❌ error … 既定でON
- ⚠️ warning … 既定でON
- 💡 suggestion … **既定でOFF**（必要なものだけ足す）

## 6. モードの切り替え（中高生／ディレクター）

ログイン機構は入れない。このアプリの「ログイン不要」という良さを壊さないため。

| 案 | 内容 | 評価 |
|----|------|------|
| **A. 合言葉（推奨）** | 管理タブを開くと合言葉を1回聞く。合えば端末に記憶。環境変数 `DIRECTOR_PASSCODE` | ○ 軽い・既存の思想に合う・中高生の端末には出ない |
| B. URLを知っている人だけ | `/admin` を知っていれば誰でも。編集リンクと同じ考え方 | △ 企画一覧が全部見えるので、さすがに弱い |
| C. ちゃんとログイン | NextAuth等 | ✗ 人数に対して重すぎる |

**A を推奨。** 合言葉はディレクター間で共有、半年に一度変える運用で足りる。

## 7. データ設計（ここが実装の山場）

### 7-1. 足りないもの

いまの保存は **IDを知らないと何も取り出せない** 形。

```js
// checkStore.js / surveyStore.js
createCheck(data) → { id, ... }   // 作る
getCheck(id)      → record        // IDを知っていれば読める
// ↑ 一覧を返す関数がない
```

ディレクター管理画面は「一覧」が前提なので、**インデックスを足す**必要がある。

### 7-2. 企画（project）を中心に据える

```
project（企画）
├─ id, name（ワークショップ名）, owner（アミーゴ名）, eventDate
├─ status: draft | checked | fb_sent | fixing | ok
├─ checks: [checkId, checkId, ...]      ← 何度でもチェックできる
├─ feedbacks: [{ at, by, message, channel }]
├─ forms: { registrationId, surveyId }
└─ createdAt, updatedAt
```

これで 1章の課題 4・5・7 がまとめて解ける:
- 同じ企画のチェックとアンケートが繋がる
- 一覧が作れる
- 誰の企画か残る

### 7-3. 保存先（既存の仕組みに合わせる）

`lib/kv.js` が Redis / ファイルを吸収しているので、その上に足すだけ。

```js
// lib/projectStore.js（新規）
createProject(data)
getProject(id)
updateProject(id, patch)
listProjects()            // ← 新しく必要なもの

// 実装:
// Redis … poster:project:{id} に本体、poster:index:projects（LIST）にID
// ファイル … data/projects/{id}.json ＋ data/projects/_index.json
```

> ⚠️ Redis の `KEYS` は使わない（Upstashの無料枠で遅い・非推奨）。IDのリストを別に持つ。

### 7-4. 中高生側は端末内でよい

中高生は「自分が作ったものだけ」見られればよいので、
サーバに持たずlocalStorageで足りる。

```js
// localStorage: "poster-check:mine"
[{ kind: "check", id, name, at }, { kind: "survey", id, name, at }, ...]
```

**Phase 1 はこれだけで「アンケートに辿り着けない」問題が解ける。**
企画モデル（7-2）はディレクター管理画面（Phase 3）と同時でよい。

## 9. スマホ操作性の基準

タブを入れる以上、下まわりは全部見直しになる。決めておく数値:

| 項目 | 基準 | なぜ |
|------|------|------|
| タブの高さ | 56px ＋ `env(safe-area-inset-bottom)` | iPhoneのホームバーに隠れないため |
| `main` の下余白 | 現状 96px → **タブ分 +64px** | 最後の要素がタブに隠れる事故を防ぐ |
| タップ領域 | 最低 44×44px | 現状 `.mini-copy` は34〜40px程度で、指が太いと外す |
| 入力欄の文字 | **16px以上** | iOS Safariが自動ズームするのを防ぐ（現状 `.rule-input` は0.95rem≒15.2pxで**ズームする**） |
| 主ボタン | 画面下に sticky | 長い結果を見たあと、上に戻らず押せる |
| ポスタープレビュー | `max-height: 55vh` | 現状340px固定。縦長ポスターが潰れる |
| 横スクロール | 禁止 | `.script-box`（黒いコード欄）は折りたたみへ |
| QRコード | 折りたたみ | 使うのは印刷時だけ。常時156px占有は重い |
| 写真の入口 | 撮影を第一候補に | `capture` 付きの入口を分ける。現場で撮ってすぐ確認できる |

既存CSSは `app/globals.css` の Nova デザインシステム（インディゴ基調）をそのまま使う。**色やトーンは変えない。**

## 11. 確認したいこと

実装前に、ここだけ答えがほしい。

1. **「アミーゴ」= ポスターを作る中高生本人、という理解で合っているか？**
   （FB文の宛名・言葉づかいがこれで決まる）
2. **FBは何で送っている？** LINE／メール／口頭？
   → LINEなら改行多め・短め、メールなら件名と署名つきで作る
3. **ディレクターは何人くらい？** 合言葉1つの共有でよいか
4. **アミーゴの名前はどこで入れる？** いまは「作成者名」だけ。チェック時にも聞く形でよいか
5. **タブは3つで確定か。** 中高生に管理タブは見せない想定でよいか
6. 中高生にもアカウントらしきもの（名前の記憶）は要るか、端末に覚えるだけでよいか
7. 「言い方（やさしめ／ふつう／しっかり）」の3段階で足りるか
